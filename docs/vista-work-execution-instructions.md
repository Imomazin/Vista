# Vista Work Execution Instructions

## Objective

Transform the existing Vista repository into a striking, functional marketing superior intelligence platform, retaining the work already present. The product must look premium and cinematic, and its intelligence features must deliver verifiable outcomes.

## Starting point

- GitHub repository: Imomazin/Vista, main branch.
- Vercel project: vista. Intended domain: vista.ambidexters.com.
- Read the complete current source tree and these documents first:
  - docs/vista-transformation-blueprint.md
  - docs/vista-execution-backlog.md
  - docs/ecosystem.md
  - docs/roadmap.md
- The repository is currently public. Do not commit customer records, credentials, secrets or unreleased commercial intelligence.
- Existing functionality includes a Canvas 3D V, an entrance, nine-engine directory, HTML audits, competitor comparisons, scoped multi-page investigation, local drafts, project/browser workspace, action board, exports and basic tests.
- Avoid replacing existing working code with disconnected mockups.

## Priority order

1. Verify the live deployment and establish real screenshots and user-flow results across desktop, tablet and mobile. Check domain routing, runtime failures, browser console errors, navigation and the audit API.
2. Preserve a baseline branch, capture current behaviour, run typecheck/build/tests and identify functional regressions and security gaps.
3. Introduce a unified premium design system across the app with an editorial cinematic entrance and sophisticated, dense but navigable intelligence workspace.
4. Prototype and deliver a solid, dimensional, premium rotating V emblem with refined lighting, realistic geometry, low-power fallback, pause and reduced-motion support.
5. Make the Command Centre a real multi-engine workspace with truthful source indicators, interactive evidence views and clear actions; demonstrate coherent information architecture even before external connections.
6. Implement secure identity, organisations, project access, persistent data and localStorage migration before onboarding real clients.
7. Expand the audit/crawler and prioritization engine, adding measurements with source attribution and no fabricated values.
8. Connect user-approved first-party sources, initially Google Search Console and GA4, using secure OAuth and explicit property selection.
9. Deliver evidence-grounded GEO/AI Exposure sampling in a controlled pilot, with provenance, prompt versions, competitors and denominators.
10. Expand content workflows, client operations, reporting and remaining engines while maintaining the highest design and technical standards.

## Concrete visual bar

- Cinematic does not mean slow or cluttered. The brand V must be solid and physically legible throughout rotation.
- First impression: carefully composed question, oversized editorial typography, atmospheric but restrained effects, premium materials and a concise invitation to enter.
- Application: executive pulse, trusted connected data, flexible drilldowns, compelling maps/charts where source-appropriate, meaningful comparison panels, side-by-side evidence and actionable priorities.
- Interactions: subtle but convincing hover/click/transition physics, high-quality chart motion, keyboard shortcuts, responsive typography and coherent mobile navigation.
- Meet WCAG 2.2 AA and reduced-motion needs. Protect Core Web Vitals and deliver fallbacks if 3D fails.
- No empty shiny cards, phantom live dashboards or controls without an implemented action.

## Engineering and data safeguards

- Preserve the current domain, Ambidexters branding, five pillars and nine-engine taxonomy.
- Use small, reviewable PRs and preview deployments. Never silently overwrite or remove working features.
- Protect tenant boundaries at every database query and mutation, log important actions and manage scoped roles.
- Keep user approval for publishing, outreach, spend and external mutations.
- All external intelligence must carry provider/source, timestamps, locale, metrics definition and uncertainty.
- Respect provider terms, copyright, data collection rules and quotas. Do not scrape private conversations or invent AI visibility figures.
- Strengthen outbound crawl URL safety, rate limiting, monitoring, background jobs, backup and secrets.
- Validate existing browser records before importing into cloud and preserve user export/recovery.

## Acceptance steps

For each release, demonstrate:
- actual screenshots or a screen recording of key desktop and mobile flows;
- working click paths, data states and concrete before/after differences;
- passing typecheck/build/tests and core end-to-end tests;
- evidence for accessibility, responsive performance and security checks;
- source provenance for any intelligence metric;
- preview URL and change summary;
- a list of incomplete features without misrepresenting readiness.

## Initial output from Work

Start by reporting the exact verified deployment state, current functional audit and a prioritized list of engineering tasks, then begin implementation of the visual foundations and functional dashboard. Make forward progress in the same working session, producing actual code, tests and preview builds where permitted. Prioritize visual excellence and a working product equally.
